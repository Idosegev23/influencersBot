# Mami Meeting Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One self-contained interactive HTML file that plays two scripted 3-phone WhatsApp scenarios for tomorrow's Mami meeting.

**Architecture:** A static beat-player: `SCENARIOS` data array + a renderer that draws three WhatsApp phone mockups and replays beats 0..N on next/prev/autoplay. No backend, no AI, no external assets.

**Tech Stack:** Plain HTML/CSS/JS in one file. Hebrew, RTL. Spec: `docs/superpowers/specs/2026-08-12-mami-demo-design.md`.

## Global Constraints

- Single file `docs/demos/mami-demo.html`; zero external requests (works offline).
- All copy in Hebrew; page `dir="rtl"`.
- Three phones: לקוחה (שירה) / ספק / שירות לקוחות מאמי.
- Chrome: scenario switcher, simulated clock chip, case-status chip, "כללי מאמי" card, narration strip, controls (הבא/הקודם/אתחול/אוטו).
- Escalation in 3 layers: SLA spine, styled escalation card in CS phone, customer churn-intent bump.
- No test framework — verification is a manual click-through of every beat in both scenarios (demo page, presented once).

### Task 1: Page skeleton + beat player engine

**Files:**
- Create: `docs/demos/mami-demo.html`

**Interfaces:**
- Produces: beat schema consumed by Task 2/3 data:
  `{phone: 'customer'|'supplier'|'cs', from: 'them'|'bestie', type: 'bubble'|'system'|'log'|'escalation', text, narration?, clockJump?, status?, urgent?}`
  and player functions `renderUpTo(n)`, `next()`, `prev()`, `restart()`, `setScenario(i)`, `toggleAuto()`.

- [ ] **Step 1:** Build the static stage: header (title + scenario tabs + clock chip + status chip), "כללי מאמי" rules card, three phone mockups (WhatsApp header with avatar/name, scrollable message area, authentic green/white bubble styling, ticks), narration strip, control buttons. Placeholder beats array with 3 dummy beats to drive development.
- [ ] **Step 2:** Implement the player: state `{scenario, beatIndex}`; `renderUpTo(n)` clears phones and re-renders beats 0..n (accumulating clock time and status); `next()` animates only the newest beat (typing indicator ~600ms → bubble), highlights the active phone, dims others, updates narration/clock/status; `prev()`/`restart()` re-render; autoplay = 4s interval; scenario tabs call `setScenario`.
- [ ] **Step 3:** Open in browser, click through dummy beats, verify RTL, highlight/dim, clock and status chips, controls.
- [ ] **Step 4:** Commit: `git add docs/demos/mami-demo.html && git commit -m "feat(demo): mami demo stage + beat player"`
